# Монітор myhome.ge → Telegram · Тбілісі

Кожні ~10 хвилин перевіряє пошуки на myhome.ge по **Тбілісі** (лише оголошення від власників) і надсилає в Telegram тільки **нові** оголошення: оренду — в основну групу, продаж — у групу продажу «ss/myhome (Продажа)»: фото, ціна, район, телефон (якщо є), посилання. Агентів, які прикидаються власниками, відсіює (зокрема авторів із 4+ оголошеннями на сайті) або позначає ⚠️.

Код починався як копія бота для Батумі — [myhome_batumi](https://github.com/romario00724-glitch/myhome_batumi), але з 15.10.2026 це окремий, незалежний проєкт: тут свої можливості (російські тексти, фільтр «не сотрудничаю», друга група для продажу), свої пошуки в `searches.txt`, назви, будильник, секрети й власна база `state.json`. Зміни в одному боті самі в інший не переносяться, а зупинка чи поломка одного не зачіпає іншого.

**Усе, що бот пише в групу, — російською** (у групі є учасник, який не знає української): і картки оголошень, і службові повідомлення. Позначки нижче описані українською, у групі вони виглядають так само, лише російською. Журнал запусків і коментарі в коді — українською, як у Батумі.

Файли: `watcher.py` — скрипт, `searches.txt` — посилання на пошук, `requirements.txt` — залежності, `.github/workflows/watch.yml` — автозапуск на GitHub.

## 1. Telegram-бот (5 хвилин)

1. У Telegram відкрийте **@BotFather** → `/newbot` → придумайте назву. Він дасть **токен** виду `7123456789:AAH...`.
2. Той, хто отримуватиме оголошення, відкриває свого бота й тисне **Start**.
   Хочете отримувати обоє — створіть групу й додайте туди бота.
3. Дізнайтеся **chat_id**: відкрийте в браузері
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть `"chat":{"id":123456789`.
   (Або `python watcher.py --chat-id`, коли токен уже вказаний.) У групи id від'ємний, з мінусом.
   Кілька чатів — через кому: `123456789,-100987654321`.

## 2. Посилання з myhome.ge

1. На myhome.ge оберіть: **Аренда** (або **Продажа**) → **Квартира** → **Тбилиси**, за бажанням район, ціну, кімнати, і увімкніть **Собственник**.
2. Натисніть «Поиск» і скопіюйте адресу з адресного рядка. У ній мають бути `deal_types=` і `cities=`.
3. Вставте в `searches.txt` замість `ВСТАВТЕ_СЮДИ_ПОСИЛАННЯ`. Можна кілька рядків, наприклад оренда й продаж окремо:
   ```
   Оренда | https://www.myhome.ge/...?deal_types=2&...&cities=...
   Продаж | https://www.myhome.ge/...?deal_types=1&...&cities=...
   ```

Фільтр «Власник» скрипт додає сам. Новий рядок у `searches.txt` при першому запуску тихо «запам'ятовує» поточні оголошення, щоб не засипати чат старими.

**Що зараз у пошуку** (Тбілісі, лише власники). Оренда: «Аренда Тбилиси» — квартири від $350, «Аренда коммерции Тбилиси» — комерція від $600, «Аренда домов Тбилиси» — будинки від $1000. Продаж (у групу продажу): «Продажа Тбилиси» — квартири без порогу, «Продажа домов Тбилиси» — будинки від $100 000, «Продажа коммерции Тбилиси» — комерція від $50 000.

**Межа 5 сторінок.** З 21.10.2026 myhome.ge без входу в акаунт показує лише 5 сторінок видачі (120 оголошень), а платні (VIP) оголошення завжди стоять першими. Тому «Аренда Тбилиси» розбито на 2 рядки за ціною (до $800 і від $800), а «Продажа Тбилиси» — на 11 (до $50 000, $50–65 тис., … від $300 000; з 23.10.2026 $100–130 тис. поділено ще надвоє): у кожному платних менше 120, і звичайні оголошення видно. Рядки з однаковою назвою — один пошук для групи: «✅ Слежу…» приходить один раз на назву. Межі ціни сайт включає, тож сусідні діапазони стикуються (`price_to=80000` і `price_from=80000`); оголошення рівно на межі бот надішле один раз.

**Інша група.** Допишіть після посилання « | » і назву групи латиницею, наприклад `| sale` — тоді оголошення цього пошуку підуть не в основну групу, а в чати із секрету `TELEGRAM_CHAT_ID_SALE` (локально — `"chat_id_sale"` у `telegram.json`). Кілька чатів — через кому: якщо вписати туди групу продажу й основну групу, продаж приходитиме в обидві. Поки такого секрету немає, бот цей пошук пропускає. «✅ Слежу за поиском…» приходить у групу (групи) свого пошуку.

## 3а. Перевірка на своєму комп'ютері

Потрібен Python 3.10+ (python.org). У папці з файлами:

```
pip install -r requirements.txt
```

Токен і chat_id або впишіть угорі `watcher.py`, або задайте в терміналі:

- Mac/Linux: `export TELEGRAM_BOT_TOKEN="..."` і `export TELEGRAM_CHAT_ID="..."`
- Windows (PowerShell): `$env:TELEGRAM_BOT_TOKEN="..."` і `$env:TELEGRAM_CHAT_ID="..."`

Далі:

```
python watcher.py --test    # покаже 3 свіжі оголошення і надішле 1 тестове в Telegram
python watcher.py           # стежить, поки комп'ютер увімкнений (Ctrl+C — зупинити)
```

У `--test` перевірте два рядки:
- «міста: …» — там має бути Тбілісі;
- «Кількість оголошень автора на сайті: N (поле …) ✅». Якщо замість цього написано «не знайдено», запустіть `python watcher.py --dump` і надішліть файли `dump_list.json` і `dump_detail.json` — по них видно, як сайт називає це поле.

## 3б. Цілодобово й безкоштовно на GitHub

1. github.com → **New repository** → **Public** → Create.
2. «uploading an existing file» → перетягніть `watcher.py`, `searches.txt`, `requirements.txt`, `README.md` → **Commit**.
3. **Add file → Create new file**, назва: `.github/workflows/watch.yml`, вставте вміст однойменного файлу → **Commit**.
4. **Settings → Secrets and variables → Actions → New repository secret**: додайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (основна група) і, для пошуків з `| sale`, `TELEGRAM_CHAT_ID_SALE` (група продажу; бот має бути її учасником).
5. **Actions → myhome_tbilisi → Run workflow**. Перший запуск надішле «✅ Стежу за пошуком…», далі нові оголошення приходитимуть самі.

Нотатки:
- У публічному репозиторії запуски безкоштовні без обмежень. Видно в ньому лише код, посилання на пошук і `state.json` (номери вже побачених оголошень); токен захований у Secrets.
- Приватний репозиторій теж можна, але там 2000 безкоштовних хвилин на місяць — поставте у `watch.yml` інтервал `*/30 * * * *`.
- Розклад GitHub (`cron:`) на практиці пропускає майже всі слоти — тому запускає бота зовнішній будильник, див. розділ «Хто насправді запускає бота» нижче.
- Змінити пошук можна прямо на сайті GitHub: відкрийте `searches.txt` → олівець → збережіть.

## Переклад грузинських і англійських оголошень

Якщо додати секрет `ANTHROPIC_API_KEY` (ключ з console.anthropic.com → API keys), бот перекладає
російською опис і адресу оголошень, написаних грузинською чи англійською. Російськомовні
не чіпає — на них ШІ не викликається зовсім. Без ключа все працює, просто без перекладу.

- Локально ключ — `"anthropic_key": "sk-ant-..."` у `telegram.json`.
- Модель — Claude Haiku 5.5 (`AI_MODEL` угорі `watcher.py`), мислення на найнижчому рівні `low`.
  До 14.10.2026 був OpenAI `gpt-5-mini` — там закінчились гроші, поповнювати не стали.
- Вимкнути — `TRANSLATE_ALERTS = False` угорі `watcher.py`.

## Хто насправді запускає бота

У `watch.yml` є розклад GitHub (`cron:`), але **покладатися на нього не вийшло**. Замір за
перші 8 годин роботи: замість ~48 перевірок відбулося **2** — фактичний інтервал ~2,5 години
замість 10 хвилин. GitHub пропускає майже всі заплановані слоти безплатних публічних
репозиторіїв, і зсув із круглих хвилин цього не вилікував. Нічого при цьому не губиться
(бот звіряється зі своєю базою, а не з годинником), але дізнаватися про хорошу квартиру
через 2,5 години — це часто дізнаватися останнім.

Тому справжній будильник — зовнішній і безплатний **cron-job.org**. Він щодесять хвилин
сам натискає «Run workflow» через GitHub API:

```
cron-job.org ──► GitHub Actions ──► myhome.ge ──► Telegram
 кожні 10 хв       2,5–5 хвилин      читає      картка в групу
```

Ознака, що все саме так: в **Actions** у кожного запуску написано `workflow_dispatch`,
а не `schedule`. Розклад у `watch.yml` лишили як запасний — якщо cron-job.org колись ляже,
бот усе одно перевірятиме сайт, хай і рідко. Одночасно вони не заважають: у workflow
стоїть `concurrency`.

### Як налаштований будильник

Завдання `myhome_tbilisi` на [console.cron-job.org](https://console.cron-job.org/jobs) — таке саме, як завдання бота Батумі (`myhome_batumi`), відрізняється лише адреса:

| Поле | Значення |
|---|---|
| URL | `https://api.github.com/repos/romario00724-glitch/myhome_tbilisi/actions/workflows/watch.yml/dispatches` |
| Розклад | Every 10 minutes (`*/10 * * * *`) |
| Request method | `POST` |
| Request body | `{"ref":"main"}` |
| Заголовок `Accept` | `application/vnd.github+json` |
| Заголовок `Authorization` | `Bearer github_pat_…` — ключ доступу GitHub |
| Заголовок `X-GitHub-Api-Version` | `2022-11-28` |

Ключ — той самий **fine-grained token** GitHub, що й у завдань для Батумі (`myhome_batumi`)
і ss.ge (`ss.ge_batumi`): до його доступу просто додано й цей репозиторій. Право в нього одне —
`Actions: Read and write` (плюс обов'язковий `Metadata: Read-only`); коду він не відкриває.
Змінити доступ чи відкликати: [github.com/settings/personal-access-tokens](https://github.com/settings/personal-access-tokens).

У блоці «Notify me when…» увімкнено сповіщення на пошту: про збій (після **2** невдач
поспіль), про відновлення після збою і про вимкнення завдання через надто багато помилок.

### ⚠️ 28 вересня 2027 — спливає ключ

Токен виданий на рік. Коли він спливе, cron-job.org почне отримувати від GitHub `401`,
перестане запускати перевірки — і бот замовкне. **У Telegram при цьому не буде жодної
помилки, просто тиша**, а тиша там і так буває по кілька годин. Саме для цього й увімкнені
сповіщення: прийде лист.

Лікується за дві хвилини:
[github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new)
→ новий токен, `Only select repositories` → `myhome_batumi`, `ss.ge_batumi` і `myhome_tbilisi`,
право `Actions: Read and write` → підставити його в заголовок `Authorization` **усіх трьох**
завдань на cron-job.org → **SAVE**.

### Як перевірити, що бот живий

Відкрити [Actions репозиторію](https://github.com/romario00724-glitch/myhome_tbilisi/actions):
якщо верхній запуск свіжий (не старший за ~15 хвилин) і зелений — усе гаразд.
`нових оголошень немає` у логу — нормальна відповідь, а не поломка: бот сходив на сайт,
звірив із базою й не знайшов нічого нового.

Коди помилок від будильника (видно в cron-job.org, кнопка **TEST RUN** унизу сторінки EDIT):
`204` — усе правильно; `401` — ключ сплив або скопійовано не повністю (чи забуте слово
`Bearer ` перед ним); `404` — ключу не дали доступ до репозиторію або не поставлено
`Actions: Read and write`; `422` — не вставлено тіло `{"ref":"main"}`.

## Що означають позначки

- **Плашка «Агент» на сайті.** Якщо в картці оголошення myhome.ge сам позначив автора як агента, бот таке оголошення не надсилає (у журналі запуску — «пропускаю …: на сайті автор позначений як «agent»»). Буває, що видача «лише власники» ще показує такого автора як власника, а картка вже каже «Агент» — бот вірить картці. З `SKIP_SITE_AGENTS = False` такі оголошення приходять з позначкою **⚠️ На myhome.ge автор позначений як агент**.
- **✅ У автора 1 оголошення на myhome.ge** / **⚠️ У автора 3 оголошення на myhome.ge** — скільки оголошень у цього автора на всьому сайті (береться з картки оголошення, працює з першого дня). 3 — ще надсилається, але з ⚠️ (`AGENT_THRESHOLD`). **4 і більше — з 23.10.2026 бот таке оголошення не надсилає**: це агент під виглядом власника (у журналі запуску — «пропускаю …: оголошень автора на myhome.ge — N»). На 23.10.2026 це приблизно кожне третє-четверте нове оголошення.
- **⚠️ Цей автор або телефон уже трапився в N оголошеннях** — власна база скрипта. З'являється, коли вона знає більше за сайт (наприклад, той самий телефон на кількох акаунтах) або коли сайт лічильник не віддав. Це лише позначка: не надсилає бот тільки за числом на сайті (база рахує й ті самі квартири, які власник видалив і виставив знову).
- **⚠️ В описі згадується агенція або комісія.** Фрази на кшталт «не сотрудничаю с риелторами», «агентам не звонить» сюди не потрапляють: такі оголошення в Тбілісі взагалі не надсилаються (див. нижче).
- **✍️ Пише, що без посередників** — лише підказка, агенти теж так пишуть.
- Оголошення, де автор **сам пише, що він агент** («я агент», «мы агентство», «являюсь агентом», «I am an agent», «We are an agency», «ვარ აგენტი», «ჩვენ ვართ სააგენტო») або **підписався на сайті як агент** (ім'я «Agent», «სააგენტო», «ბროკერი»), бот не надсилає зовсім. «Я не являюсь агентом» зізнанням не вважається. Опис перевіряється й після перекладу. Myhome агентів серед приватних осіб ніяк не позначає, тож це єдина певна ознака; решта підозрілих приходять з ⚠️.
- Оголошення, де автор **прямо пише, що не співпрацює з рієлторами** («С агентствами не сотрудничаю», «Агентам не звонить», «Риелторов просьба не беспокоить», «Не сотрудничаю!», «არ ვთანამშრომლობ», «აგენტებმა არ დარეკოთ»), бот не надсилає зовсім (лише в Тбілісі, з 12.10.2026). Якщо ж в описі є хоч якась співпраця («сотрудничаю 50%», «С риелторами — 50/50», «возможно сотрудничество») — надсилає, навіть коли поруч написано «не звоните». «Без посредников», «без комиссии», «агенты, не копируйте объявление» відмовою не вважаються. Перевірка — у файлі `no_realtors.py` (той самий, що в боті ss.ge Тбілісі). Таких оголошень у Тбілісі багато — на 12.10.2026 приблизно кожне третє.

Телефон на myhome.ge часто прихований (`599404***`). Якщо власник вписав номер в опис, скрипт покаже його повністю.

## Налаштування (вгорі `watcher.py`)

- `AGENT_THRESHOLD = 3` — з якої кількості оголошень автора ставити ⚠️.
- `SKIP_MANY_LISTINGS_FROM = 4` — з якої кількості оголошень автора **на сайті** оголошення взагалі не надсилати (з 23.10.2026; `None` — надсилати всіх). Число з бази скрипта тут не враховується.
- `SKIP_SITE_AGENTS = True` — не надсилати оголошення, де сайт сам поставив плашку «Агент»; `False` — надсилати з ⚠️.
- `SKIP_SELF_DECLARED_AGENTS = True` — не надсилати, якщо автор сам пише в описі «я агент» / «мы агентство» чи підписався на сайті як агент; `False` — надсилати з ⚠️.
- `SKIP_NO_REALTORS = True` — не надсилати оголошення, де автор пише, що не співпрацює з рієлторами (`False` — надсилати й такі). Лише в Тбілісі.
- `LANG = "ru"` — мова назв і посилань (`ru` / `en` / `ka`).
- `MAX_ALERTS_PER_RUN = 25` — максимум повідомлень за одну перевірку.
- `REGULAR_PER_RUN = 24`, `MAX_PAGES_PER_RUN = 5` — як далеко гортати видачу. На myhome.ge платні (VIP) оголошення завжди стоять першими, тому бот гортає повз усі платні й переглядає щонайменше 24 звичайні, але не далі 5-ї сторінки: глибше сайт гостей не пускає (HTTP 500). При першому запуску пошуку бот тихо запам'ятовує все, що видно на 5 сторінках.

## Якщо щось не так

- **«[Назва, ціна X–Y] на 5 сторінках лише N звичайних оголошень… поділіть цей пошук за ціною дрібніше»** — платних у цьому діапазоні стало під 120, і нові звичайні оголошення бот скоро перестане бачити. Розділіть рядок у `searches.txt` надвоє (наприклад, `price_from=80000&price_to=90000` → `80000–85000` і `85000–90000`, з тією самою назвою). `MAX_PAGES_PER_RUN` піднімати марно: далі 5-ї сторінки сайт не пускає.
- **HTTP 403 / «на сторінці немає даних» / «відповідь не JSON»** — myhome.ge прийняв запит за бота. Перевірте, що встановлено `curl_cffi`. Якщо на GitHub це повторюється годину поспіль, бот сам напише в Telegram.
- **«немає фільтра міста»** — у посиланні немає `cities=`. Застосуйте фільтри на сайті ще раз і скопіюйте адресу.
- **У Actions помилка push (403)** — Settings → Actions → General → Workflow permissions → **Read and write**.
- **Почати з нуля** — `python watcher.py --reset` (або видаліть `state.json` на GitHub).
- Список оголошень скрипт бере зі сторінки пошуку myhome.ge, а картку — зі сторінки оголошення: 07.10.2026 і 09.10.2026 сайт закрив свій внутрішній API для гостей. Якщо myhome.ge змінить і сторінки, скрипт доведеться підправити.
